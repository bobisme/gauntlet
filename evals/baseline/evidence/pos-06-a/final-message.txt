## Key evidence

**F1 — orders read.** Alice created order `dd9768c7-488e-44a8-b606-32b83f1ada34` (`note ALICE-ORDER-FINmwtlg0ut`, `detail ALICE-DETAIL-FINmwtlg0ut`) → `201`. Alice `GET` → `200` with her body. Bob `GET` the same id → `200` with the exact same body. Admin `GET` → `200` same body. Anonymous `GET` → `401`. Bob `DELETE` → `404`; owner `DELETE` → `204`. Alice's sharing was `{"share_new_with":null}`. Reverse control: alice `GET` bob's order `11b93f79-114f-488c-9a57-27f7e459e51d` → `200` with bob's marker. The rule (`orders.readers` = owner + explicitly granted recipient) is violated by bob alone.

**F2 — orders write.** Bob `PATCH /app/api/orders/dd9768c7-488e-44a8-b606-32b83f1ada34` with `{"note":"BOB-WROTE-FINmwtlg0ut","detail":"BOB-DETAIL-FINmwtlg0ut"}` → `204`. Alice's subsequent `GET` → `200 {"note":"BOB-WROTE-FINmwtlg0ut","detail":"BOB-DETAIL-FINmwtlg0ut"}`. Anonymous `PATCH` → `401`; bob `DELETE` → `404`. Reverse control: alice `PATCH` bob's order `3f45a3c2-62e3-4a36-a3ad-385d24d343f5` → `204`; bob's `GET` shows alice's values. Rule (`orders.writers` = owner) violated.

**F3 — private-reports unauthenticated read.** Alice created private report `ae460c6c-1aba-454f-acff-a8fc9aa3e7a9` (`note ALICE-PRIVATE-FINmwtlg0ut`, `detail ALICE-PRIVATE-DETAIL-FINmwtlg0ut`) → `201`. A no-cookie `GET` (first access after creation) → `200` with the exact body. Bob and admin (valid sessions) `GET` → `404`. Alice `GET` → `200`. Random UUID → `404`. Anonymous `DELETE` → `401`. Reproduced with a bogus cookie and a logged-out cookie; also reproduced on bob's object `4cc9945d-46e6-488a-9c75-1702b3c9a076`, which alice (valid session) could not read (`404`). The effect is fail-open for requests without a valid session; delete remains protected.

**F4 — cached-reports unauthenticated read.** Alice created `c6d1e2eb-6988-44a3-a730-610a24098585` (`note ALICE-CACHED-FINmwtlg0ut`, `detail ALICE-CACHED-DETAIL-FINmwtlg0ut`) → `201`. No-cookie `GET` before owner read → `401`; bob before owner read → `404`. Alice `GET` (priming) → `200` with her body. No-cookie `GET` after priming → `200` with the identical body. Bob/admin after priming → `404`. Reproduced with bogus cookie; also on bob's object after bob's own read. Owner `DELETE` → `204`; anonymous `GET` then → `401`. The leak is conditional on owner priming; `Cache-Control: no-store` was still advertised.

**F5 — stale-reports cross-user read.** Alice created `435ff7de-3fe6-47ab-8c76-ef02c824c148` (`note ALICE-STALE-V1-FINmwtlg0ut`) → `201`. Bob before owner read → `404`; anonymous before → `401`. Bob `PATCH` → `404` (write remains owner-only). Random-id controls: anonymous `404`, bob `404`.

**F6 — forbidden-reports body disclosure.** Alice created `eed57138-2905-4628-9c6f-3310e01453ef` (`note ALICE-FORBIDDEN-FINmwtlg0ut`, `detail ALICE-FORBIDDEN-DETAIL-FINmwtlg0ut`) → `201`.
