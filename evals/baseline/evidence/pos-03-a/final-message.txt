Assessment complete. Report written to `/workspace/report.md`; raw request/response evidence is in `/workspace/evidence.log`.

## Supported findings

1. **`orders` / read — cross-user IDOR**  
   `user-bob` read `user-alice`'s unshared order (`200`, exact `note`/`detail`), with no prior owner read required.

2. **`orders` / update — cross-user IDOR**  
   `user-bob` `PATCH`ed `user-alice`'s order (`204`), and the change persisted. A non-recipient admin and a sharing recipient were also able to `PATCH` a shared order. Deletion remained owner-only.

3. **`stale_reports` / read — stale-cache cross-user/unauthenticated read**  
   Bob got `404` before the owner read; after alice read the object, bob got `200` with her `note`/`detail`. After cache population, anonymous and invalid-cookie requests also got the data. Update/delete remained protected.

4. **`forbidden_reports` / read — protected data in `403` body**  
   Bob, admin, and anonymous requests received `403` but the body contained the owner's exact `note` and `detail` (byte-identical to the owner's `200` body). Unknown id returned `404`.

5. **`echo_reports` / read — global cross-user note disclosure**  
   Reads return a global `echoes` array containing other users' notes; the path id is ignored (unknown id returns the same list) and no session is required.

6. **`private_reports` / read — unauthenticated read**  
   Anonymous, explicit-empty-cookie, and invalid-session requests read another user's `note`/`detail` (`200`), while authenticated non-owners (`bob`, `admin`, `alice` on bob's object) correctly got `404`.

## Controls / non-findings

`invoices`, `tenant_notes`, `bulletins`, `catalog`, `cached_reports`, and `expiring_reports` were exercised for create/read/update/delete with owner, authenticated non-owner, anonymous, invalid-session, unknown-id, and sharing baselines. No cross-user access was found there within the tested scope. `orders` delete, `stale_reports` update/delete, and deletes on other classes remained owner-only.

## Observations not submitted as findings

- **`login_reports`**: existing-inaccessible ids return `200` HTML “Sign in required” vs `404` for unknown ids — an existence oracle, but no `note` content disclosed.
- **`expiring_reports`**: owner read invalidated the owner's session; no cross-user read observed.

Scope exercised was only `http://127.0.0.1:3000/app/` via the local pinned proxy listener `127.0.0.1:46785`; no other target was assessed.
