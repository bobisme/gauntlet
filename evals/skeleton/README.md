# Skeleton trial rubric

Freeze the assignment before launch and record every attempt. Replay the rubric with the same assignment, ledger, and settled files.

```sh
python3 -I evals/scripts/lib/skeleton_grade.py assignment.json ledger.json \
  --artifact-root "$run_root" --monitor-key "$private_monitor_key"
python3 -B evals/scripts/test-skeleton-grade.py
```

Exit 0 means all gates passed. Exit 1 emits structured JSON for failed, unmeasured, or invalid cells. Exit 2 means the assignment or ledger could not be interpreted. The three checked-in prompts supply an objective, ordinary help permission, or the entry-only question. The scripted tests create complete synthetic evidence trees in disposable directories. They establish offline replay behavior only.

## Assignment and ledger

[The v1 JSON schema](ledger-v1.schema.json) defines the assignment and ledger shape. Replay checks file bytes, references, and outcomes. A file reference has a relative `path` and a `sha256`. All references resolve under the artifact root. Evidence for an attempt stays under its attempt ID. The referee writes the assignment, ledger, and every review and process projection outside the worker's access.

- Assign one unique attempt ID to each of `executable/supplied`, `executable/discovery`, `managed/supplied`, and `managed/discovery`. Put every launched attempt in the ledger with its intended cell. Later reruns use `selection: "unassigned"` and remain visible with their capture status. An unattempted slot is unmeasured. A launched slot with invalid evidence retains its denominator and has a null score.
- Freeze the exact prompt files, model and settings, executable, harness and fixture digests, and the oracle ID, version and digest. Pin the collector executable's SHA-256 and the SHA-256 commitment of its 32-byte random monitor key before launch. For each assignment pin the canonical native engagement manifest, its chronological `manifest_history`, and the exact protected declaration and pass bytes used at admission. The trusted referee retains the unmodified Investigation `show --depth full` response for the prepared manifest's sealed Run in protected storage and freezes its path and SHA-256 as `manifest_capture`. The grader relies on the referee for the prelaunch response's process provenance. The fixture producer in `crates/scourge/src/demo.rs::retain_manifest` attaches and seals one original named `engagement` and puts that retained identity in the verifier authority. The grader binds the receipt's case, artifact, revision, and bytes to the manifest reads and expects that specific Artifact to have no transforms. The private case key pins the property identity, including its digest, and the expected exposure for determinate cases. F-37 has its own scripted attempt ID, preparation evidence and supplied lead ID.
- For each supplied cell, freeze the exact lead ID from its own prepared engagement. The two supplied cells require distinct IDs. Each discovery cell has a null supplied lead. The visible inventory maps workspace-relative paths to digests. The executable and managed inventories within a track share the same paths, with `AGENTS.md` added in the managed cell. The native workspace files `scourge.toml`, `.scourge/demo-owner` and `.scourge/state.sqlite3` can have different bytes for each independently prepared workspace. `workspace_config` references the exact native version-1 TOML with its generated workspace UUID. Replay requires a distinct UUID from those inventory-bound bytes for each of the four cells. Freeze the exact start and end markers and hashed body of the managed guide, which comprises the complete `AGENTS.md` file.
- Bind the ledger and each scored referee receipt to the SHA-256 of the exact frozen assignment file. A capture entry names the capture settlement receipt, retained raw transcript, and independent referee receipt. Refer to the final capture at `ATTEMPT/capture.json` and retained transcript at `ATTEMPT/retained/raw/transcript.jsonl`. A launched slot with missing capture materials stays invalid.
- Capture must be `scourge.trial-capture` version 1, settled and valid, with a null capture score, typed capacity and filesystem write-probe receipt, passed boundary checks, and successful process settlement. Replay compares the listed directories and files with the actual retained tree, then checks file bytes, terminal event, and event prefix. The rubric writes its score to stdout.
- Copy the exact checked-in prompts and installed managed guide. The grader checks the observed prompt against these frozen bytes, so restaging an assignment with case-specific coaching fails. Each discovery slot freezes an independent `discovery_review` with schema `scourge.skeleton-discovery-input-review.v1`, source `fixture-referee`, its attempt ID, prompt and manifest hashes, exact visible path-to-artifact references, and an empty `hints` list. Replay hashes the reviewed workspace files against the observed inventory.
- Pin the exact fixture operation registry artifact and its compiled digest. The grader checks the registry snapshot against the pinned native operation and declaration source identities. An admissible case uses one of the registered resources, its exact operations and ordered plant selectors, and the registered identity probe. [Native registry snapshot](native-fixture-registry.v1.json)

Keep source captures and native artifacts in the settled `ATTEMPT/retained/artifacts/` tree. The referee links these originals to the assignment. ## Host trace authentication

Keep the private monitor key in host-controlled storage outside the worker environment, artifact root and referee projection inputs. Only the host collector can issue traces. The offline reviewer supplies the same private key through `--monitor-key`. The grader checks its prelaunch SHA-256 commitment. The key is never a field in any retained artifact or result.

The collector associates native command items with process trees through its host execution boundary. Close and drain those trees and check event-loss counters before authenticating the receipt. A command with no child execution can have an empty `executions` list when the collector actually observed its complete tree. A projected command list alone does not establish that.

The [schema](ledger-v1.schema.json) defines the envelope. Authenticate the `trace` object by taking HMAC-SHA-256 with the monitor key over the ASCII schema ID `scourge.skeleton-host-process-trace.v1`, a zero byte, and compact JSON with recursively sorted object keys and ASCII escaping. Write the lowercase hex authenticator as `hmac_sha256`. The signed trace binds the exact assignment and raw transcript hashes, attempt, session and monitor identity. A missing signature, command receipt, or closed lossless tree makes the attempt ineligible for claim scoring. Native integration must supply an independently qualified host collector.

Pin `teapot_sha256`, `investigation_sha256` and `investigation_exec_path` before launch. Freeze each attempt's `teapot_exec_path` from its prepared native authority. The trial uses the historical Teapot binary. The collector labels staged preparation executions `teapot-preparation`. Verify evidence requires `teapot-verifier`, the role for the descriptor-bound historical verifier child being qualified in bn-1r9u. The standalone `teapot` role covers the separate request-reference qualification. Retain exact stdout for the signed verify subprocesses with their tool role, native process and parent identities, exec path, argv, binary digest, and exit. The collector records `approved_child_processes` on the Scourge execution. Each `child_originals` row identifies a `process_id` and `file`, and each `edit_surface_originals` row also identifies the `operation` and `session` (null for non-session reads). Keep these bytes in the protected retained inventory. The grader derives the Teapot schema lane from the authenticated executable pin and checks the matching instrument identity, command and order. It hashes the compact native result and derives the report before checking that the surface admits verification.

The native verify replay follows the global signed child order across both tools. It consumes both Teapot gates, every accounting operation, each pre-dispatch flow floor, and the exact send and flow read-back for each registered action. Each stdout envelope must satisfy its frozen Teapot schema. The send must establish the recorded flow, and its read-back must hash to the retained original. The number of sends fits the frozen dispatch plan and admitted request bound. Investigation must read the exact admitted manifest before Teapot admission, then open and read back the capture's run before attaching the start observation. Each flow attachment follows that flow's read-back and precedes the next Teapot operation. Finalization and recovery follow the closing gate and attachments. The two run reads link canonical Investigation IDs to the Scourge run ID and qualified Investigation identity. Begin and finalize commit keys, attachment sizes, request digests and acceptance times must match the native receipt chain and ordered recovery inventory.

The replay checks authenticated selectors and exact bytes for the admitted manifest and experiment, each record-lineage original, and the published record. Before a selector can use an Artifact, replay follows its current Source and transform references in native depth-first order under the same snapshot. Source records carry their own revision and evidentiary-use state. The experiment derives from exactly the admitted manifest, with a fresh complete manifest walk after Teapot admission and immediately before the signed ingest. Its ingestion command key derives from the request key agreed by Scourge verify and run read-back. Replay requires the ingest describe, the strict JSON and byte read-back, and the separate full Experiment describe immediately before capture begin.

After capture, publication preparation reads every canonical record input and independently rereads the experiment and selected oracle originals. The publication derives from the verification record's ordered original references and the experiment. Between the pre-ingest publication lookup and ingest, replay requires fresh full lineage walks for the canonical input list at a common snapshot. Both derivations bind native transformation names, versions, input identities, digests, and observed revisions. The publication ingest describe, committed lookup and describe, record read, and repeated original-input and oracle reads must occur in native order. After reopening Investigation, the coherent finding read brackets the manifest, historical record chain, current published record, and current lead's inputs with matching manifest checkpoints. Every record must decode as canonical VerificationV1 using the same wire registry as Scourge. Historical records must also bind exactly the ordered inputs declared by their typed fields and their uniquely digest-bound Experiment. The coherent read collects originals for the current lead and still validates the records and derivations of other leads. Each required observation comes from a distinct signed process execution.

## Prepared sessions and fixture identity

Before freezing the assignment, the protected fixture referee records its unique reset ID and pins a `session_access` receipt for each assigned case. The receipt identifies the attempt, case property, manifest, reset, simulated environment, prepared target and instrument. For every declared session reference it binds the effective instrument session name, credential digest, subject digest and original successful native identity probe. Keep original requests with session cookies in protected evidence. Neither the credentials nor the subject strings belong in a score. The signed host trace binds the assignment that pins these receipts.

Replay selects the declared verifier session when present, falling back to the exploration session. It checks that the cookie and observed subject of each recorded role match the corresponding protected probe. Probe subjects remain opaque values independent of the principal labels. The same-subject case must have two distinct admitted cookies that the protected verifier probes observed resolving to one subject.

The record must identify the exact prepared target, including its chosen port and any native addresses, and each replayed request must address that target. The raw accounting observations must use the protected pass ID, digest, request ceiling, and native `pass_file` bound by fixture preparation. Replay checks the native version, jobs and pass samples around traffic, and the compiled owner-session macro dry run and request bound before it. Before counters establish admission. After counters may be unavailable in the authenticated sample. Replay checks continuity for observed counters and reports unestablished per-run attribution. The number of retained rounds and admission request bound follow the actual verify argv. An omitted `--rounds` uses the native default of two. Both instrument gates must show clean rule, interception, script, session and configuration surfaces with their successful version-bookended reads. Native M1 scores require shared custody, separate unconfined principals, simulated acquisition and unenforced operation, consistent with the admitted engagement's custody and enforcement requirements. The record must carry false values for destination/time and request-ceiling enforcement.

A positive requires a native `finding.status: "verified"` badge whose deciding and status records link the matching finalized run, oracle, property, published record, retained originals and admitted denying policy. The public case requires a corresponding `refuted` badge and admitted public policy. M1 puts the engaged policy in the manifest referenced by the experiment. The policy-rule field on that native record is null.

Each graded round links the identity probes I1–I4, plants P and P2, and reads F0–F4 to complete Teapot originals. Replay checks the registered order, contiguous step groups, advancing flow IDs and nondecreasing native timestamps. Each registered dispatch produces one request. The live path uses default `SendOptions` without redirect following, and the admitted gates require sessions with no login, logout or CSRF behavior. Anonymous probes must contain no fixture credential. Replay checks a fresh, distinct canary for every native declared field of each plant, verifies the observed crossed fields, and corroborates controls, exposure and after-owner-read. It matches response bodies with the compiled M1 HTTP decoder binding of 1 MiB and 100× expansion and uses Teapot's already dechunked payload when the response head names chunked transfer. The scored lane requires both cleanup DELETE observations and checks their aggregate outcome. Scoring a cleanup without a retained DELETE will require an authenticated export of the native per-object cleanup rows. The login and same-subject controls require finalized invalid records and native observations corroborating `OBSERVER_INVALID` and `SAME_SUBJECT`, respectively. A missing control stays unmeasured.
